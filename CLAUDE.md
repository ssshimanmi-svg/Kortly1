# Kortly

Сайт-каталог спортивных площадок Москвы (бадминтон, настольный теннис, сквош).
Работает как витрина-справочник: бронирования внутри сайта нет, запись идёт на сайте площадки или по телефону.

Живёт на **kortly.ru**.

## Стек

- **React 18** + **Vite 8**
- Плагинов у Vite нет: JSX собирается встроенным esbuild, весь конфиг — одна строка `base: "/"`
- **Tailwind CSS** — подключён через CDN прямо в `index.html` (решение уровня MVP, не через сборку)
- **Яндекс.Метрика** — счётчик в `index.html`

## Структура

Кода немного, всего три файла:

- `src/App.jsx` — **вся логика и вся вёрстка**: фильтры, поиск, сортировка, модалки, галерея, шапка, подвал
- `src/data/venues.js` — **данные площадок**: адрес, метро, телефон, сайт, часы работы, фото, цены (`min` и `prime`)
- `src/main.jsx` — точка входа, ничего больше

Картинки площадок лежат в `public/img/`, пути строятся через `import.meta.env.BASE_URL`.

## Ветки и рабочий процесс

Две ветки:

- **`sanctuary`** — черновик. **Все изменения вносятся сюда.**
- **`prod`** — основная, то, что уходит в продакшн.

Порядок работы — строго такой:

1. Обсуждаем, что нужно сделать.
2. Claude вносит изменения **только в `sanctuary`**.
3. Владелец проверяет результат.
4. Владелец **сам вручную** мерджит `sanctuary` → `prod` и деплоит.

### Что Claude делать не должен

- **Не мерджить `sanctuary` в `prod`.** Это делает владелец руками.
- **Не запускать `npm run deploy`** и никак иначе не деплоить. Деплой — только вручную владельцем.
- **Не коммитить в `prod`.**

Смысл правила: прод не должен ломаться, поэтому между черновиком и публикацией всегда стоит ручная проверка человеком.

### Деплой (справочно, выполняет владелец)

```
npm run deploy
```

Собирает проект, кладёт `kortly.ru` в `dist/CNAME` и публикует `dist` на ветку `gh-pages` репозитория `ssshimanmi-svg/Kortly1`.

## Команды

- `npm run dev` — локальный сервер разработки
- `npm run build` — сборка
